# 🛡️ الدستور الجنائي الشامل والموحد — أرشيف التحقق الجنائي السيادي (بروتوكول رقم 606 المصفى)

**الجهة المصدرة:** مدير عمليات الإعلام الآلي ومهندس النظم السيادية المحترف.  
**الموجه إليهم:** المالك والمستشار التقني السيادي، والمطورون البشريون (كريم وأحمد).  
**الحالة التنفيذية الراهنة:** 🛑 **تجميد تام ومطلق (Zero Code Execution — Forensic Audit & Permanent Archive Only).**  
**طبيعة الوثيقة:** هيكلة موحدة وجامعة تلغي كافة أشكال التكرار والازدواج، وتدمج كافة السجلات الجنائية السابقة (`ARC-606-01` إلى `ARC-606-06`) في مرجع قطعي واحد غير قابل للتجزئة.

## الباب الأول: سجل التحكيم وتفنيد الادعاءات الباطلة

بناءً على الفحص المتقاطع الحي في صلب الشجرة البرمجية، تم تفنيد وإسقاط الادعاءات التالية نهائياً، وتبرئة ساحة المطورين منها:

1. **فرية تسرب النهر الإعلاني أثناء البحث:**
   * *الادعاء السابق:* زُعم أن الإعلانات تظهر للراكب أثناء انتظار العروض إذا لم يتوفر كباتن.
   * *الحقيقة البرمجية الدامغة:* دالة `shouldShowAdRiver` تحجب الإعلانات قطعياً (`return false`) ما دامت حالة الشاشة `RECEIVING_OFFERS`. الكود سليم دستورياً.
2. **فرية اختفاء ملف المناعة السلوكية:**
   * *الادعاء السابق:* زُعم أن ملف `anti-cheat-kernel.ts` مفقود أو غير موجود.
   * *الحقيقة البرمجية الدامغة:* الملف موجود في `src/core/logic/anti-cheat-kernel.ts` وحجمه 4,285 بايت، الخلل الحقيقي فيه يقتصر على اعتماده على `localStorage` وليس غيابه.
3. **فرية الملفات الوهمية والأحجام المفبركة:**
   * *الادعاء السابق:* زُعم وجود ملف باسم `request-ride-modal.tsx`، وأن ملف `captain-offer-card.tsx` يبلغ 865 سطراً.
   * *الحقيقة البرمجية الدامغة:* لا يوجد أي ملف باسم `request-ride-modal.tsx` (ملف مختلق بالكامل)، وملف `captain-offer-card.tsx` يبلغ 254 سطراً فقط (تحت السقف الدستوري 300 سطر).

## الباب الثاني: المصفوفة الجنائية الموحدة للفضائح الكودية

### المحور 1: النواة والأمان وقواعد البيانات

#### 1. ثغرة إغراق خلايا H3 بالطلبات المتزامنة (Anti-Flood Guard)
* **الموقع:** `supabase/migrations/20260704_core_production_functions.sql` (الأسطر 724-728) و `src/features/rider/services/rider-server-marketplace.ts` (الأسطر 110-145).
* **الدليل الكودي:**
  ```sql
  create policy ride_requests_insert_own_pending on public.ride_requests
  for insert to authenticated
  with check (rider_id = (select auth.uid()) and upper(coalesce(status::text, '')) = 'PENDING');
  ```
* **التشخيص والضرر:** عملية إدخال (`insert`) مباشرة وعارية من العميل دون قيد فريد جزئي (`Unique Partial Index`). يستطيع أي مستخدم أو روبوت إطلاق عشرات الطلبات المتزامنة في نفس الخلية السداسية H3، مما يشل صالة المزاد ويغرق رادارات الكباتن.
* **التصحيح الحتمي:** إنشاء الفهرس الجزئي الفريد:
  `CREATE UNIQUE INDEX unique_active_rider_request ON public.ride_requests (rider_id) WHERE status IN ('PENDING', 'ACCEPTED', 'ARRIVED', 'TRIP_ACTIVE');`

#### 2. ثغرة الإلغاء الأحادي للرحلة النشطة (Mid-Trip Breach)
* **الموقع:** `supabase/migrations/20260704_core_production_functions.sql` (الأسطر 327-329 داخل دالة `cancel_ride_request`).
* **الدليل الكودي:**
  ```sql
  if upper(coalesce(req.status::text, '')) in ('COMPLETED', 'CANCELLED') then
    raise exception 'ride_request_closed';
  end if;
  ```
* **التشخيص والضرر:** الدالة تمنع الإلغاء فقط للرحلات المغلقة مسبقاً، وتسمح للراكب بإلغاء رحلة في حالة `ACCEPTED` أو `TRIP_ACTIVE` بضغطة زر بينما يتحرك الكابتن ميدانياً، مما يهدر حقوق الناقلين.
* **التصحيح الحتمي:** قفل الإلغاء التلقائي فور قبول الرحلة أو سريانها، ورفض الإلغاء إذا كانت الحالة `ARRIVED` أو `TRIP_ACTIVE`.

#### 3. وهمية المناعة السلوكية وتخزينها في المتصفح (Phantom LocalStorage Immunity)
* **الموقع:** `src/core/logic/anti-cheat-kernel.ts` (الأسطر 110-128) و `rider-state-machine.ts` (الأسطر 316-325).
* **الدليل الكودي:**
  ```typescript
  const RIDER_IMMUNITY_STORAGE_KEY_PREFIX = 'radar_rider_immunity_';
  export function saveStoredRiderImmunity(record: RiderImmunityRecord): void {
    localStorage.setItem(`${RIDER_IMMUNITY_STORAGE_KEY_PREFIX}${record.riderId}`, JSON.stringify(record));
  }
  ```
* **التشخيص والضرر:** تخزين العقوبات وسجل الإلغاءات في `localStorage` يتيح للراكب تصفير عداد العقوبات وإعادة رصيده إلى 5.0 بمجرد مسح بيانات المتصفح، مما يعطل ميكانيكية الهبوط تحت 4.2 كلياً.
* **التصحيح الحتمي:** ترحيل حقل `immunity_score` وسجل الإلغاءات إلى جدول `public.profiles` على السيرفر، مع خصم (-0.5) تلقائياً عند كل إلغاء تعسفي.

#### 4. تغييب بوابة السحاب والحقن المباشر في قاعدة البيانات (Bypassed Gateway)
* **الموقع:** `src/features/rider/services/rider-server-marketplace.ts` (الأسطر 180-195).
* **الدليل الكودي:** الواجهة في المتصفح تستدعي مباشرة:
  ```typescript
  const { data, error } = await client.from('ride_requests').insert(payload)...
  ```
* **التشخيص والضرر:** غياب طبقة وسيطة تحكم دورة حجز الرحلات؛ المتصفح يتصل بجدول قاعدة البيانات مباشرة مما يفتح الباب للتلاعب بالحمولة وتجاوز محددات التسعير والتحقق من الهوية.
* **التصحيح الحتمي:** حصر إنشاء الرحلات خلف دالة سحابية RPC محصنة (`p_create_ride_request`).

### المحور 2: التسعير والملاحة وبروتوكول انعدام الكباتن

#### 5. انتهاك توقيت بروتوكول انعدام الكباتن (Zero-Captain Fallout)
* **الموقع:** `src/features/rider/hooks/use-offers-lifecycle.ts` (الأسطر 19، 134).
* **الدليل الكودي:**
  ```typescript
  const OFFER_TIMEOUT_MS = 240 * 1000; // أو 300 * 1000 في بعض المواضع
  const remainingMs = Math.max(0, OFFER_TIMEOUT_MS - elapsed);
  ```
* **التشخيص والضرر:** مخالفة صريحة لنص الباب الثاني من الدستور الذي يفرض 180 ثانية حتمية (3 دقائق)؛ مما يحبس الراكب في رادار وهمي يستنزف البطارية في مناطق خالية من السائقين.
* **التصحيح الحتمي:** تثبيت الثابت دستورياً على `180 * 1000` (180,000ms) دون أي هامش للمناورة.

#### 6. تجاوز المهلة الملاحية وحلقة الانتظار المركبة (OSRM Timeout Loophole)
* **الموقع:** `src/lib/road-route.ts` (الأسطر 68-94، 455-475).
* **الدليل الكودي:**
  ```typescript
  const ROUTE_PROVIDERS = ['mapbox', 'valhalla', 'osrm', 'proxy'] as const;
  const ROUTE_TIMEOUT_MS = 1500;
  const ROUTE_FETCH_ATTEMPTS = 2; // محاولتان لكل موفر!
  ```
* **التشخيص والضرر:** الالتفاف على سقف الـ 1500ms للهبوط الآمن بإجراء محاولتين عبر 4 موفرين، مما يعلق الراكب لمدد تتراوح بين 3000ms إلى 4500ms عند بطء الشبكة.
* **التصحيح الحتمي:** ضبط `ROUTE_FETCH_ATTEMPTS = 1` وإلغاء خيار `proxy`، والتحول الفوري والمباشر لمعادلة الهرسين (Haversine × 1.3) فور تجاوز 1500ms.

#### 7. شلل التسعير عند الموقع الافتراضي (Initial Location & Fallback Trap)
* **الموقع:** `src/features/rider/hooks/use-rider-geolocation.ts` (السطر 14) و `use-server-fare-and-route.ts` (الأسطر 76-88).
* **الدليل الكودي:** الموقع الافتراضي مشفر على القاهرة `(lat: 30.0444, lng: 31.2357)` وحالته `'fallback'`؛ والشرط في خطاف التسعير ينص على:
  `const hasUsableRiderLocation = ... && riderLocationStatus !== 'fallback';`
* **التشخيص والضرر:** عند تأخر الـ GPS، يظل الموقع في حالة `'fallback'` فيصبح `isRouteEstimateLoading = true` دائماً، ويتجمد زر "اطلب الآن" نهائياً.
* **التصحيح الحتمي:** اعتماد موقع عمان كمركز ابتدائي افتراضي، والسماح بحساب التسعير عبر الهرسين حتى في حالة `fallback`.

#### 8. ارتداد الوكيل الملاحي العقيم (Redundant Routing Proxy Echo)
* **الموقع:** `src/server/api/road-route.ts` (الأسطر 1-70) المربوط في `server.ts` (السطر 99).
* **التشخيص والضرر:** السيرفر يستدعي دالة `fetchRoadRoute` التي تستعلم نفس الخوادم العامة المجانية (OSRM و Valhalla) دون وجود خادم OSRM محلي خاص، مما يضيف 3000ms زمن استجابة دون أي فائدة.
* **التصحيح الحتمي:** حذف المسار العقيم واستبداله بالسقوط المباشر على الحساب الرياضي الداخلي.

### المحور 3: متلازمة الصدى المزدوج وتضارب الحقيقة (SSOT Breaches)

#### 9. حلقة صدى تأكيد الوجهة المتكررة (Dual Destination Echo Loop)
* **الموقع:** `src/features/rider/hooks/use-ride-request-status-sync.ts` (الأسطر 65-76) مع `rider-view.tsx` (الأسطر 68-93).
* **الدليل الكودي:** دالة `openDestination` ترسل `CONFIRM_DESTINATION`، وبجوارها `useEffect` موازٍ يعيد إطلاق نفس الإجراء فوراً عند كل اهتزاز طفيف في إحداثيات الـ GPS!
* **التشخيص والضرر:** إطلاق مزدوج يستنزف المعالج ويعيد حساب مسار OSRM عشرات المرات.
* **التصحيح الحتمي:** إعدام الـ `useEffect` التلقائي وحصر تأكيد الوجهة بنبضة المستخدم اليتيمة (Click / Drag End).

#### 10. مرآة المعرف الموازي الشبح (Shadow Ref for Offer ID)
* **الموقع:** `src/features/rider/hooks/use-offers-lifecycle.ts` (الأسطر 42، 250) مع `use-ride-request-status-sync.ts` (الأسطر 182-186).
* **الدليل الكودي:** إنشاء `pendingAcceptedOfferIdRef = React.useRef(null)` وتصفيره محلياً في الخطاف دون إخطار آلة الحالة المركزية.
* **التشخيص والضرر:** انقسام الحقيقة بين الـ Reducer والـ Ref مسبباً شلل الراكب عند انقطاع الاتصال وإعادة فتحه.
* **التصحيح الحتمي:** استئصال الـ Ref الشبح والاعتماد حصرياً على `state.pendingAcceptedOfferId`.

#### 11. انفصام الكباتن المفضلين (Favorite Captains Split-Brain)
* **الموقع:** `use-history-state.ts` (الأسطر 412، 445) مقابل `use-offers-lifecycle.ts` (السطر 59).
* **الدليل الكودي:** شاشة السجل تحفظ المفضل في `localStorage` وقاعدة البيانات، بينما رادار العروض يستعلم جدول `dexieDb.favoriteCaptains` القديم والمهجور.
* **التشخيص والضرر:** عدم ظهور الكباتن المفضلين في أعلى رادار العروض أبداً.
* **التصحيح الحتمي:** إبادة جدول Dexie القديم وتوحيد القراءة عبر `dexieDb.favoriteCaptainIds`.

#### 12. تنازع وتصادم صدى الإلغاء (Cancel Request Collision)
* **الموقع:** `use-send-cancel-ride-request.ts` (السطر 231) مع `rider-state-machine.ts` (الأسطر 324-326).
* **الدليل الكودي:** الإلغاء المحلي يعيد الراكب فوراً إلى الخريطة (`RESET_TO_IDLE`)، ثم بعد 200ms تصل نبضة السيرفر المتأخرة `REQUEST_CANCELLED` فتعيده قسراً لشاشة العروض الخالية!
* **التصحيح الحتمي:** تعديل الـ Reducer لرفض إجراء `REQUEST_CANCELLED` إذا كانت الشاشة قد استقرت على `IDLE_MAP`.

#### 13. التأتأة الصوتية المتزامنة (Concurrent Acoustic Echo)
* **الموقع:** `rider-server-marketplace.ts` (الأسطر 305، 355) مع `use-ride-request-status-sync.ts` (الأسطر 195-210).
* **الدليل الكودي:** حقن `new Audio('/sounds/notification.mp3').play()` داخل دوال الاشتراكات السحابية، بالتزامن مع إطلاق نغمات وتنبيهات من خطافات الواجهة لنفس الحدث.
* **التصحيح الحتمي:** حذف كائنات `Audio` كلياً من ملفات السيرفر والخدمات، وحصرها في طبقة الـ UI مع قفل زمني (Debounce 500ms).

#### 14. صدى سجل الرحلات وإهمال تطهير الـ 72 ساعة
* **الموقع:** `use-history-state.ts` (الأسطر 145-175) و `src/lib/dexie-db.ts` (السطر 191).
* **التشخيص والضرر:** ضرب السيرفر بـ 3 استعلامات متتالية عند فتح السجل متجاهلاً ذاكرة `dexieDb.riderTripLedger` المحلية، مع بقاء دالة `purgeExpiredRiderTrips()` مهجورة دون أي استدعاء.
* **التصحيح الحتمي:** تفعيل القراءة من الذاكرة المحلية أولاً (Cache-First 0ms) ثم المزامنة بالخلفية، واستدعاء دالة التطهير عند إقلاع التطبيق.

### المحور 4: التوأمة الشبحية والأوامر المهجورة والمونوليث

#### 15. التوأمة الشبحية لفك روابط الخرائط (The Ghost Twinning)
* **التوأم المهجور (Ghost):** مسار `POST /api/sovereign-digger` في `server.ts` (الأسطر 170-310) مع `src/lib/sovereign-digger.ts` (130 سطراً ميتة دون أي استدعاء 0 Callers)، وتشغيل مؤقت نبضي كل دقيقة لكنس كاش فارغ!
* **التوأم الحي (Active):** مسار `src/app/api/maps/resolve/route.ts` مع `src/shared/services/google-maps-location.ts` المستدعى فعلياً في `useClipboardLocationImport.ts`.
* **التصحيح الحتمي:** حذف مسار `/api/sovereign-digger` ومؤقت الكاش من `server.ts`، وحذف `src/lib/sovereign-digger.ts`.

#### 16. المجرفة الميكانيكية الشبحية (`/api/cleanup`)
* **الموقع:** `src/server/api/cleanup.ts` (الأسطر 1-135) المربوط في `server.ts` (السطر 98).
* **التشخيص والضرر:** مسار مهجور لا يستدعيه أي كود في التطبيق (0 Calls). يستعلم ويحذف من Firestore المهجور (`trips` و `users`)، بينما تعمل رحلات الركاب الحقيقية على Supabase وتتراكم دون حذف.
* **التصحيح الحتمي:** حذف الملف وإلغاء ربطه، ونقل كنس الـ 72 ساعة لـ `pg_cron` داخل PostgreSQL.

#### 17. الواجهة والمزود الشبح (`RiderOperationsProvider`)
* **الموقع:** `src/features/rider/hooks/use-rider-operations.tsx` (الأسطر 60، 86-98، 108-130) و `rider-workspace.tsx` (السطر 12).
* **الدليل الكودي:** تثبيت `tripStatus: 'idle'` أبدياً وكافة الدوال تعيد وعوداً فارغة `Promise.resolve()`.
* **التشخيص والضرر:** عمى هيكلي تام للواجهة عن الحالات الحرجة للرحلة.
* **التصحيح الحتمي:** استئصال المزود المهجور بالكامل من شجرة المكونات.

#### 18. صخرة المونوليث المتضخمة (The 739-Line Monolith)
* **الموقع:** `src/features/rider/services/rider-server-marketplace.ts` (739 سطراً).
* **التشخيص والضرر:** دمج 5 أنظمة متعارضة في ملف واحد متضخم بنسبة 84% فوق السقف الدستوري.
* **التصحيح الحتمي:** تفكيك الملف إلى 3 وحدات ذرية:
